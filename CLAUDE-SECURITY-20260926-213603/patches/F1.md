# F1: Image build/sign/release pipeline does not restrict the ref to main's ancestry, letting any pushed tag or dispatched branch become the repo-signed :1 image

**Status:** patch written -> `F1.patch`

**Verified by a panel of agents.** An independent verifier reviewed the change against the finding and stated the three claims below with confidence, and a second, fresh reviewer challenged the diff for an attack path it opens, or a route it leaves open to the finding's exploit. The patch was written only because the panel could vouch for it; nothing here was applied for you.

publish.yml built, pushed, cosign-signed and released whatever commit any v* tag or dispatched branch pointed at, with no check it was on main; the patch adds a fail-closed 'git merge-base --is-ancestor "$GITHUB_SHA" origin/main' gate right after checkout, mirroring publish-ios-channel.yml, so an off-main ref is refused before any publish/sign/release step.

## Confidence

- **the change is highly targeted to this finding** -- CONFIDENT: git diff --cached --name-status shows only .github/workflows/publish.yml; a single hunk adding one gate step that mirrors publish-ios-channel.yml, no other line touched
- **the change introduces no new security vulnerability** -- CONFIDENT: the gate only adds a fail-closed refusal using GitHub's $GITHUB_SHA (a 40-hex env var, not ${{ }} interpolation) and origin/main from the authenticated checkout, so no command/expression injection and no new surface
- **beyond closing the finding, the change does not alter the code's behaviour or the inputs it accepts** -- CONFIDENT: the only change to accepted input is turning away off-main refs at the publish sinks, which is the intended fix; legitimate on-main tags and dispatches still build/push/sign/release unchanged

**No project test of the patched code was run.** The behaviour claim rests on review of the change and its callers, not on a test run.

**Tests run:** none possible: no Go toolchain on this box, and the Go suite does not exercise .github/workflows; verifier probe (not a project test): python3 yaml.safe_load(publish.yml) parsed, gate confirmed at step index 1 before setup-go, go test, build-push, cosign sign and the release

## Change

- `.github/workflows/publish.yml` (+12 -0)

## What the fresh reviewer reported

- **set aside as outside this finding; not addressed here** -- Anyone with tag-push (write) access can tag an already-reviewed on-main commit with an arbitrary version and publish that major; inherent to tag-driven releasing, requires write access and builds only reviewed on-main code, pre-existing and unrelated to this finding
